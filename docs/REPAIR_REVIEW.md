## البيانات والأمان

- لا تُحذف الحسابات أو الطلبات أو العناوين بالمزامنة. عينة الكتالوج لها معرّفات ثابتة وتُحدّث داخل transaction.
- React لا يستورد كتالوج JSON ولا يعرض بديلًا ثابتًا عند تعطل API؛ البيانات المعروضة تأتي من MySQL.
- النسخة الاحتياطية المحلية مشفرة، ومجلد النسخ الخاصة مستبعد من Git.
- أسرار MySQL وPaymob وJWT تبقى في الباك وإعدادات الاستضافة.
- الدفع يعتمد على callback المتحقق منه، ولا يصبح ناجحًا لمجرد رجوع المتصفح من بوابة الدفع.
- لم تُوسّع صلاحيات محضر الطلبات لكل المطاعم؛ تعيين الموظف لمطعم يحتاج علاقة ملكية وصلاحيات مقيدة قبل إتاحته.

## النتيجة وحدود التحقق

تطبقت migrations وتزامن كتالوج الإنتاج، ونجحت جاهزية الباك وقراءة الكتالوج عبر Vercel. نجح بناء الفرونت وفحص Python syntax والمراجعة اليدوية للكتالوج في المتصفح المحلي والمنشور، دون أخطاء JavaScript أو CSP في النسخة النهائية. الأدلة والحدود في [سجل التحقق](SPRINT_2_VERIFICATION.md).

Paymob مضبوط على Sandbox، ولم يُنفذ دفع حقيقي. لم تُجر تجارب حسابات OAuth أو إرسال بريد في هذه المراجعة، ولم تُكتب أو تُشغّل unit/integration/end-to-end test suites حسب طلب صاحب المشروع.
