# واجهة المطاعم الديمو

واجهة رئيسية محلية بالكامل: ٤ مطاعم، وكل مطعم فيه ٣ أكلات. مصدر المعلومات ملف JavaScript عادي. لا يوجد ربط للمطاعم أو الأكلات بالباك، ولا تعديل في قاعدة البيانات.

## التشغيل والمسارات

من مجلد `front`:

```bash
npm run dev
```

- الرئيسية: `http://127.0.0.1:5173/#/`.
- مثال قائمة مطعم: `http://127.0.0.1:5173/#/restaurants/bun-and-bite`.
- الدخول والحساب يظلان على مساراتهما السابقة، ومنها `/#/login` و`/#/account`.

الرئيسية والقوائم لا تحتاج تسجيل دخول أو سيرفر باك. `SessionProvider` يحيط بفرع صفحات التسجيل والحساب فقط؛ لذلك تصفح الديمو لا يبدأ طلب refresh للجلسة. اختيار مصدر بيانات الحساب `VITE_DATA_SOURCE=api` أو `demo` لا يغير مصدر بيانات المطاعم؛ المطاعم ديمو في الحالتين.

## مكان تعديل البيانات

[restaurants.js](../src/features/catalog/data/restaurants.js) يحتوي:

- `restaurantCategories`: فلاتر نوع الأكل.
- `demoRestaurants`: المطاعم، والتقييمات، ووقت ورسوم التوصيل التجريبية، وقوائم الأكلات.

كل مطعم له `id` فريد يستخدم في رابط قائمته، و`name` و`category` و`cuisine` و`description` و`rating` و`deliveryMinutes` و`deliveryFee` و`artwork`، ومصفوفة `meals` فيها ثلاث وجبات بالضبط. أرقام الأسعار ورسوم التوصيل بالجنيه المصري، ويحولها العرض إلى نص منسق عند إظهارها.

كل وجبة لها `id` فريد، و`name` و`description` و`price` و`ingredients` و`artwork`. قيم `artwork` المدعومة: `burger` أو `pizza` أو `bowl` أو `wrap`. الرسومات SVG محلية داخل مكون React، ولا تحتاج صورًا خارجية أو اتصالًا بخدمة صور.

الملف JavaScript كما هو مطلوب، مع JSDoc يشير إلى نماذج TypeScript. إعدادا `allowJs` و`checkJs` يسمحان لفحص الأنواع بمراجعة البيانات. نوع `Restaurant.meals` هو tuple من ثلاثة عناصر، فيظهر خطأ في فحص الأنواع إذا أصبحت القائمة أقل أو أكثر من ثلاث وجبات.

## التنظيم ومسؤولية المكونات

```text
src/features/catalog/
├── domain/models.ts
├── data/restaurants.js
├── application/filter-restaurants.ts
└── presentation/
    ├── pages/restaurants-page.tsx
    ├── pages/restaurant-page.tsx
    ├── components/
    │   ├── catalog-hero.tsx
    │   ├── catalog-filters.tsx
    │   ├── restaurant-card.tsx
    │   ├── restaurant-facts.tsx
    │   ├── food-illustration.tsx
    │   ├── meal-card.tsx
    │   └── meal-details.tsx
    ├── formatters.ts
    └── catalog.css
```

| الجزء | المسؤولية |
| --- | --- |
| `CatalogLayout` داخل `app/layouts` | هيدر وتنقل وفوتر خاص بالكتالوج، وشرح نسخة الديمو |
| `RestaurantsPage` | حالات البحث والتصنيف فقط، وعرض المطاعم أو حالة البحث الفارغ |
| `filterRestaurants` | دالة مستقلة ترشح البيانات بحسب النوع واسم المطعم أو الأكلة، مع توحيد الألف والياء وتجاهل التشكيل |
| `CatalogHero` | مقدمة الصفحة وزر ينقل لقائمة المطاعم وينقل التركيز لعنوانها |
| `CatalogFilters` | حقل بحث مع مسح، وأزرار تصنيف تبين الاختيار الحالي |
| `RestaurantCard` | رابط واحد يفتح قائمة المطعم المختار |
| `RestaurantFacts` | عرض التقييم ووقت ورسوم التوصيل التجريبية |
| `RestaurantPage` | اختيار المطعم بواسطة معرف الرابط، وعرض ثلاث أكلات، وحالة المطعم غير الموجود |
| `MealCard` | اسم الوجبة ووصفها وسعرها وزر تفاصيلها |
| `MealDetails` | نافذة بالمكونات والسعر مع زر الرجوع للقائمة؛ تعيد استخدام `Dialog` المشترك |
| `FoodIllustration` | الرسومات المحلية حسب نوع الأكل |
| `formatPrice / formatNumber` | تنسيق العملة والأرقام للعربية المصرية |

الصفحات لا تستخدم `useServices` أو `useSession` أو `fetch`. البحث والتصنيف واختيار الوجبة حالات عرض محلية في React؛ لا تُحفظ في قاعدة بيانات أو التخزين المحلي. بيانات المطاعم نفسها لا تتغير عند التصفح.

## رحلة الاستخدام

1. افتح الرئيسية لترى المطاعم الأربعة.
2. ابحث باسم مطعم أو أكلة، أو اختر نوع الأكل؛ الترشيح يحدث محليًا.
3. اضغط بطاقة مطعم لتفتح قائمته ذات الثلاث أكلات.
4. اضغط «التفاصيل» لعرض المكونات والسعر، ثم ارجع للقائمة.
5. «كل المطاعم» أو شعار Foodify يرجعان للرئيسية. «حسابي» يفتح جزء الحساب الموجود سابقًا.

التصميم يدعم RTL والشاشات الصغيرة، وتسميات حقول وأزرار واضحة، وحالة التصنيف بـ `aria-pressed`، وتحديث عدد النتائج عبر `aria-live`. نافذة التفاصيل تعيد استخدام نافذة HTML الحوارية المشتركة. زر التمرير يراعي تفضيل تقليل الحركة.

هذا الجزء للعرض فقط: لا توجد سلة أو عملية إنشاء طلب أو دفع. لم تُضف أو تُشغل اختبارات؛ التحقق الفني بفحص الأنواع وبناء الإنتاج.
